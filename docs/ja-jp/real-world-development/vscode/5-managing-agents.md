Copilot をエージェントモードにすると、コードベースを調べ、変更を提案し、ファイルを編集し、コマンドを実行します。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集をリアルタイムで確認できます。差分をインラインでレビューし、個々の変更を受け入れたり取り消したりできます。エディターを離れずに、追加のプロンプトで会話を調整したり作業を広げたりできます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集をレビューして受け入れます。
- セッション中にエージェントへ指示を出し、ハイコントラストに加えてライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントが、ハイコントラストモードを実装しています。作業中、デザインチームから追加の依頼がありました。既定のテーマを暗すぎると感じる利用者向けに、ライトモードも必要です。新しい会話を最初から始めずに、既存のセッションに追加の指示を出します。

## Copilot の進捗を監視する

Copilot Chat ビューでは、エージェントが調べたファイル、実行したコマンド、提案した編集などの各手順を確認できます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案したら、差分を確認します。
   - **Keep** を選択すると変更を受け入れます。
   - **Undo** を選択すると変更を取り消し、エージェントに再度作業してもらいます。
4. チャット上部の **Files changed** を開き、このセッション中に変更されたファイル全体を確認することもできます。

> [!NOTE]
> ターミナルコマンドの実行などで許可が必要な場合、エージェントは一時停止し **Allow** を表示します。許可するのは、実行してもよいコマンドだけにしてください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に変更内容の要約が表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードの実装が終わったら、同じ会話でライトモードの切り替えも追加します。同じチャットセッションを続けるため、エージェントは変更したコンポーネント、スタイルの方法、ローカルストレージのパターンなどを引き続き利用できます。

1. Copilot Chat の入力欄に次のプロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは既存の変更を確認し、ライトモードの追加を提案します。
3. ハイコントラストモードの場合と同様に、新しい編集を確認して **Keep** または **Undo** を選択します。
4. エージェントが希望と異なる方向に進んだ場合 (たとえば、切り替え UI を意図しない方法でリファクタリングする場合) は、チャット入力欄の横にある **Stop** で停止し、追加の説明を送ります。

> [!TIP]
> 進行中のセッションに指示を加えると、最初からやり直すより早く修正できます。「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」「3つ目の切り替えを追加せず、既存の設定パネルにライトモードを統合する」「両方の切り替えにキーボードショートカットを追加する」など、調整、軌道修正、範囲の拡張を依頼できます。

## 変更されたファイルをレビューする

コミットする前に、エージェントが変更したファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイル一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. いくつかのファイルを開き、差分を確認します。カスタムエージェントが指定した ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージへの保存などが反映されていることを確認します。
4. 問題がなければ **Source Control** パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードで、進行中のセッションを監視して指示を追加しました。ファイルの編集を確認し、変更を受け入れるか取り消し、コンテキストを保ったまま追加のプロンプトを送信しました。

このレッスンでは、次のことを確認しました。

- エージェントの作業をリアルタイムで監視する
- 個々のファイル編集を受け入れる、または取り消す
- 追加のプロンプトを使って、進行中のセッションに指示する

次のレッスンでは、アクセシビリティ機能をプルリクエストとして公開し、このラボでローカルのカスタムエージェントが作成した変更をレビューします。
